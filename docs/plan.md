## 1. 执行目标与约束

实现 Spec 定义的单页任务管理应用，并提交可运行、可验证的代码。功能和验收标准以 Spec 为准，计划用于安排实施顺序。

开始前，项目负责人需将代码、本 Spec 和 Plan 提交并推送至 Git 仓库，为数字员工提供仓库地址、基础分支及工作目录。仅完成本地 commit 不代表云端已能获取代码。

本 Demo 默认在仅有上述文档、尚无应用代码的仓库中实施。若用于已有项目，先确认仓库规范、技术栈及目标目录，再同步调整两份文档，不覆盖已有业务代码。

## 3. 实施步骤

### 阶段一：读取仓库并建立基础环境

- [ ] 阅读仓库说明、贡献规范和现有代码，确认工作区状态。
- [ ] 从指定基础分支建立 `feat/task-management-demo` 工作分支。
- [ ] 在仓库根目录初始化 React + TypeScript + Vite 应用，保留现有四份文档；脚手架如要求清空目录，应改用临时目录生成并选择性复制文件，不覆盖现有内容。配置 Vitest、React Testing Library 和 jsdom。
- [ ] 配置 dev、typecheck、test、build 脚本；首次初始化使用 npm install 安装依赖并生成 package-lock.json，后续安装使用 npm ci。
- [ ] 在 README 中记录实际使用的 Node.js、npm 版本和运行命令。

完成条件：应用可启动，基础页面可打开，类型检查与构建通过，测试环境配置完成；功能测试在后续阶段补齐，不以无测试用例作为最终通过结果。

### 阶段二：实现任务数据与存储

依赖：阶段一完成。

- [ ] 定义任务类型及标题校验规则，按 Unicode 码点计算长度。
- [ ] 实现唯一 ID、创建时间和新任务插入数组首位的逻辑。
- [ ] 实现存储加载、数据校验及保存，保持显示顺序。
- [ ] 区分正常持久化和临时使用状态，避免初始化时用空数组覆盖已有数据。
- [ ] 实现异常数据、读取失败与写入失败的处理，保留规定的提示及原始数据。
- [ ] 验证存储恢复、异常结构、重复 ID 和存储失败行为。

完成条件：覆盖 Spec 的数据约定及 AC-06、AC-08、AC-09 中的存储行为。

### 阶段三：实现页面与交互

依赖：阶段二完成。

- [ ] 实现新增任务表单，支持按钮和 Enter 提交，展示校验提示。
- [ ] 实现任务列表与完成复选框，切换状态不改变排序。
- [ ] 实现全部、待办、已完成筛选及两类空状态。
- [ ] 新增和状态变更后保存数据；临时使用模式下仅更新内存。
- [ ] 实现中文提示、键盘操作、可访问名称及移动端布局。
- [ ] 使用普通文本渲染标题，并处理长标题换行。

完成条件：核心交互可运行，满足 FR-01 至 FR-07，行为与 Spec 一致。

### 阶段四：验证与修复

依赖：阶段三完成。

- [ ] 通过组件测试验证新增、长度边界、重复标题、状态切换和筛选行为。
- [ ] 验证 HTML 类输入按纯文本展示，存储异常提示能够呈现。
- [ ] 在浏览器中验证刷新恢复、键盘操作以及 375px 和 1440px 布局。
- [ ] 在干净检出中运行以下命令，修复失败后仅重跑受影响检查及最终必要检查。

```bash
npm ci
npm run typecheck
npm test -- --run
npm run build
```

完成条件：AC-01 至 AC-12 均有对应验证结果；不能验证的项目必须明确列出原因，不标记为通过。

### 阶段五：整理交付

依赖：验证完成。

- [ ] 补齐 README，包括启动步骤、检查命令及本地存储限制。
- [ ] 检查代码差异，确保未提交凭证、node_modules 或无关文件。
- [ ] 更新本计划的实际完成状态，记录偏差和未完成项。
- [ ] 提交代码并推送工作分支，按仓库流程创建待审查的变更。
- [ ] 提交执行结果说明，交由项目负责人审查、验收和合并。

## 4. 需求变更与阻塞处理

- 常规实现细节由执行者按仓库规范决定。
- 如变更涉及功能范围、数据规则或验收标准，先明确需求并更新 Spec，再同步 Plan。
- 缺少仓库访问权限或必要信息时，记录具体阻塞及需要补充的内容，继续处理不受影响的工作。
- 未获授权时不进行生产部署、不合并主分支、不引入付费服务。
