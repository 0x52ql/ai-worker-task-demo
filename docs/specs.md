# 规格说明（Spec）：内部任务管理 Demo

版本：1.0  
状态：示例，可作为新项目任务输入  
配套计划：[plan.md](./plan.md)

## 1. 背景与目标

团队需要一个简单的任务管理页面，记录待办事项并标记完成状态。本次交付一个可在本地运行的 Web 应用，验证“代码 + Spec + Plan 入库 → 数字员工执行 → 人工验收”的流程。

本文件定义做什么及验收标准，执行步骤见 plan.md。本文中的技术选型是演示约定，实际项目应按已有仓库调整。

## 2. 用户与使用场景

用户为开发团队成员。用户打开页面后可以新增任务、查看任务列表、切换完成状态，并筛选待办或已完成任务。

本 Demo 为单浏览器、单标签页使用，不涉及账号、多人共享或服务器同步；不要求处理多个标签页同时修改数据的冲突。

## 3. 功能需求

| 编号 | 功能 | 具体规则 |
|---|---|---|
| FR-01 | 新增任务 | 输入标题后点击“添加”或按 Enter 创建任务；成功后清空输入框，新任务排在最前面 |
| FR-02 | 标题校验 | 保存前去除首尾空白；处理后长度须为 1～100 个 Unicode 码点；不合法时显示中文提示、保留输入，不创建任务 |
| FR-03 | 查看列表 | 每项显示标题及完成状态；默认展示全部任务，按创建顺序倒序排列；切换完成状态不改变顺序 |
| FR-04 | 切换状态 | 使用复选框切换待办与已完成状态；已完成标题显示删除线 |
| FR-05 | 状态筛选 | 提供“全部”“待办”“已完成”三个筛选项；默认“全部”；筛选在当前页面立即生效 |
| FR-06 | 本地保存 | 新增和状态变更保存到 localStorage；刷新后任务仍在；刷新后筛选恢复为“全部” |
| FR-07 | 空状态 | 没有任何任务时显示“暂无任务，添加第一条任务吧”；有任务但当前筛选无结果时显示“当前分类暂无任务” |

补充规则：允许重复标题；在“已完成”筛选下新增待办任务时，保持当前筛选，新任务暂不显示；状态变化后不再符合筛选的任务立即从当前列表消失。

## 4. 数据约定

localStorage 键名：`company-task-demo.tasks.v1`。保存值为 JSON 数组，每个任务包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识，使用 crypto.randomUUID() 生成 |
| title | string | 校验后的任务标题 |
| completed | boolean | 新建时为 false |
| createdAt | string | 创建时间，ISO 8601 格式 |

数组顺序为列表显示顺序，新任务插入数组首位。加载时验证字段类型、标题约束（已去除首尾空白）、日期有效性和非空 ID 的唯一性。存储键不存在时按空列表初始化，属于正常状态。

异常处理：

- 保存值无法解析或存在不合法任务时，显示“本地数据异常，本次暂不保存，请清除本站存储后重试”；不加载该批任务，以空列表进入临时使用模式；本次会话禁用持久化，不覆盖原始值。
- localStorage 读取失败时，显示“无法读取本地数据，本次仅临时使用”；本次会话禁用持久化，避免覆盖未读取的数据。
- 写入失败时，保留内存中的任务并显示“保存失败，刷新后可能丢失本次修改”；本次会话后续仅临时使用。
- 上述情况均不使页面崩溃，用户仍可在当前会话操作任务。

## 5. 技术与界面要求

- 使用 React、TypeScript、Vite，使用 npm 管理依赖并提交锁文件。
- 通过 localhost 运行开发服务，使用支持 crypto.randomUUID() 的现代浏览器；远程预览应使用 HTTPS 安全上下文。
- 不引入后端、数据库、登录系统或第三方付费服务。
- 页面至少包含标题、输入区、筛选区、任务列表和提示区，文案使用中文。
- 支持键盘操作；输入框和复选框有明确的可访问名称，错误提示可被辅助技术识别。
- 在 375px 手机宽度和 1440px 桌面宽度下无横向溢出，长标题能够换行。
- 用户输入按纯文本显示，不作为 HTML 执行。

## 6. 本次不包含

- 删除、编辑标题、截止日期、负责人、优先级及拖拽排序。
- 账号登录、跨设备同步、多人协作及权限系统。
- 部署上线和接入真实公司业务数据。

## 7. 验收标准

| 编号 | 操作或条件 | 预期结果 |
|---|---|---|
| AC-01 | 输入“  编写接口文档  ”并添加 | 创建标题为“编写接口文档”的待办任务，位于列表首位，输入清空 |
| AC-02 | 提交空字符串、纯空白或 101 个 Unicode 码点 | 显示校验提示，不创建任务；100 个 Unicode 码点可正常创建（含非 BMP 字符的边界用例） |
| AC-03 | 连续创建两个同名任务 | 产生不同 ID，两条均保留，后创建的位于前面 |
| AC-04 | 勾选任务，再取消勾选 | 状态与删除线同步变化，创建顺序不变 |
| AC-05 | 分别选择三个筛选项 | 仅显示匹配状态的任务；状态变化后筛选结果立即更新 |
| AC-06 | 新增并完成一条任务后刷新 | 标题、状态及顺序保留，筛选恢复为“全部” |
| AC-07 | 空列表或筛选无匹配项 | 分别显示对应空状态文案 |
| AC-08 | 存储值为非法 JSON、非法结构或重复 ID | 显示异常提示，不崩溃，不覆盖原始存储值 |
| AC-09 | 模拟存储读取或写入失败 | 显示对应提示，当前会话仍可新增和切换状态 |
| AC-10 | 输入含 HTML 标签的标题 | 按文本显示，不执行标签或脚本 |
| AC-11 | 键盘操作及手机、桌面检查 | 核心操作可用，长标题不造成横向溢出 |
| AC-12 | 在干净检出中安装、检查并构建 | npm ci、npm run typecheck、npm test -- --run 和 npm run build 均通过 |
