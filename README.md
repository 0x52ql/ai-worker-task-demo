这是一套用于演示“云端 + 数字员工”开发流程的项目文档。示例需求是一个支持新增任务、完成状态切换、状态筛选和本地保存的任务管理页面。

```text
ai-worker-task-demo/
├── AGENTS.md
```

## 如何使用这套示例

1. 按上方目录结构将四份文档复制到目标 Git 仓库，保留 docs 子目录，按真实项目修改需求和规则。
2. 确认 Spec 的功能范围与验收标准，再确认 Plan 的实施步骤。
3. 将文档和已有项目代码提交并推送至 Git 仓库。
4. 为云端数字员工提供仓库地址、基础分支和任务目标，并配置必要的仓库访问权限。
5. 数字员工阅读文档、实现功能并提供验证结果，开发人员审查、测试后合并。

如果目标仓库已有同名文件，应合并相关内容，保留现有仓库规范。迁移文件时，应同步修改文档链接和引用路径。

## 计划实现的功能

- 新增任务，校验标题不能为空且不超过 100 个 Unicode 码点。
- 标记任务完成或恢复待办。
- 按全部、待办和已完成筛选。
- 使用 localStorage 保存任务，刷新后恢复。
- 支持中文界面、键盘操作和移动端布局。

具体规则及验收标准以 [docs/specs.md](./docs/specs.md) 为准。

## 技术方案

- React + TypeScript + Vite。
- npm 管理依赖，使用 package-lock.json 固定依赖版本。
- Vitest + React Testing Library + jsdom 验证核心行为。
- 无后端、数据库、账号登录和服务器同步。

实现时应根据所选工具版本确认 Node.js 要求，并在本节补充实际验证过的 Node.js 和 npm 版本。

## 数据与限制

- 任务保存在当前浏览器、当前站点的 localStorage 中，键名为 `company-task-demo.tasks.v1`。
- 数据不会跨浏览器或跨设备同步，清除本站存储会删除任务。
- 存储不可用时允许临时操作，并提示可能无法保留修改。
- 本次不包含编辑、删除、负责人、截止日期或多人协作功能。
- 本 Demo 使用测试任务即可，不需要真实公司业务数据。
